# WHY INTENT IS STILL NOT 10/10

## Honest Gap Analysis

### 1. It is still too app-contained
The best moments happen outside the app — while scrolling, while frozen, while avoiding. INTENT mostly waits inside the app. Widgets and notification actions exist architecturally but not as shipped product surfaces.

### 2. It is still too manual
The user must select state/time/energy too often. The commandless agent exists but needs real data to work. Day 1 users still get chips.

### 3. It still lacks real context ingestion
Pasted text extraction is keyword-based, not NLP. The Context Inbox works but feels basic compared to what a 2026 AI agent should do.

### 4. It still lacks true agentic action
Tool registry exists, handoffs exist, but no real-world action executes. Everything is draft-only. Users will notice the gap between "INTENT prepared this" and "INTENT did this."

### 5. It lacks surface-level re-entry
Widgets, App Intents, Live Activity, share extension are documented specs, not product experience. A user cannot add an INTENT widget today.

### 6. It lacks a killer viral mechanic
Share cards exist, attention receipts exist, but the "I almost drifted and got rescued" proof loop is not yet emotionally compelling enough to make someone screenshot and share.

### 7. It lacks first-week emotional progression
Onboarding works, but day 2-7 is not orchestrated with feature flags. The progression is logical but not yet coded as a state machine.

### 8. It may be over-architected relative to visible magic
12 engines, 6 services, 40+ protocol templates — but the user might only see "tap button, get mission." The magic must be visible, not hidden in architecture.

### 9. It lacks social/accountability optionality
Body double is AI-only. Accountability pacts are manual-copy. No real contact integration, no group proof, no shared wins.

### 10. It lacks a real "ambient agent" story
The market is moving toward persistent agents. INTENT's ambient mode exists but cannot truly proactively intervene without native notification scheduling, widgets, or background tasks.

## What Solves Each Gap

| Gap | Solution | Status |
|-----|----------|--------|
| App-contained | Widgets + App Intents + Live Activities | Documented, needs native build |
| Too manual | Commandless agent + personal defaults | Engine built, needs data |
| Context ingestion | NLP-based extraction | Needs native AI or cloud |
| True agentic action | Calendar/email/reminder handoffs | Draft stage, needs native APIs |
| Surface re-entry | Deep links + notification actions | Built, needs native scheduling |
| Viral mechanic | Drift Mirror + Attention Receipts | Built, needs emotional polish |
| First-week progression | Feature flag state machine | Not yet coded |
| Over-architected | Pruning + 3-tab navigation | Documented, needs UI rebuild |
| Social/accountability | Pacts with manual share | Built, needs real integration |
| Ambient agent | Background tasks + widgets | Documented, needs native build |

## The 5 Things That Would Move the Needle Most

1. **Ship Emergency Start as the default home screen** — not behind a tab, not after onboarding. One button. Now.
2. **Make Drift Mirror emotionally perfect** — the copy, the timing, the share format must feel like a personal insight, not a feature.
3. **Ship a real widget** — even a static "Rescue" button on the home screen changes the product from "app I open" to "surface that catches me."
4. **Orchestrate day 1-7** — feature flags that unlock Body Double on day 4, Context Inbox on day 5, Weekly Story on day 7.
5. **Make time-to-action under 3 seconds** — Emergency Start must feel instant. Any delay kills the magic.
